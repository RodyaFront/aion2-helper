# Браузер: уже запущенный dev-сервер

Это сценарий **браузер**. Проверка — вкладка на dev-сервере Nuxt. Electron не пересобирать и не перезапускать: ни `electron:dev`, ни `electron:build`, ни `electron .`.

Если пользователь не сказал, нужно окно Electron или уже запущенный dev-сервер в браузере — спроси, какой из двух сценариев. Не выбирай сам и не запускай команды, пока не ответит.

Все команды — из каталога `web/`. В корне репозитория `package.json` нет. Не выдумывай npm-скрипты.

## 1. Сервер и адрес

Скрипт `dev` в `web/package.json`:

```text
nuxt dev
```

Команда: `npm run dev`.

Адрес, который указывает `web/README.md`: `http://localhost:3000`. В `nuxt.config.ts` свой хост и порт не заданы.

Если `http://localhost:3000` уже открывается — новый `npm run dev` не запускай, пользуйся этим процессом. Если сервера нет и нет `web/node_modules`, сначала `npm install` в `web/` (`postinstall` запускает `nuxt prepare`), затем `npm run dev`.

`electron:dev` в этом сценарии не использовать. Он поднимает Nuxt на `http://127.0.0.1:3000` и следом открывает Electron.

## 2. Что подхватывается само

Пока работает `nuxt dev`, правки фронтенда подхватывает dev-сервер Nuxt без перезапуска: Vue-страницы и компоненты, CSS (`web/assets/css`). Отдельного скрипта hot-reload в `package.json` нет — это поведение `nuxt dev`.

Само не подхватывается, и в этом сценарии это не чинить пересборкой:

- main process: `web/electron/main.cjs`
- preload: `web/electron/preload.cjs`
- нативное: `web/electron/piper-tts.cjs`, Piper, трей, IPC
- упакованное приложение и каталоги `web/.output`, `web/release`, `dist`

Если правка только там и пользователю нужно окно приложения — это уже сценарий Electron (скилл `electron-pickup`). Не переключайся молча: скажи, что браузер это не покажет, и спроси.

## 3. Как убедиться

Открой или обнови вкладку `http://localhost:3000` и проверь изменение на странице. Окно Electron для этого сценария не открывай и не перезапускай.
